# Event App

Веб-приложение для создания мероприятий, поиска участников и общения между пользователями.

Пользователи могут создавать и публиковать мероприятия, откликаться на события других пользователей, принимать или отклонять заявки, общаться в realtime-чате, оставлять отзывы, блокировать других пользователей и отправлять жалобы.

Для модерации предусмотрена административная панель на Filament.

Проект построен на Laravel и запускается через Docker Compose. Для основной базы данных используется PostgreSQL, для очередей и кэша — Redis, а realtime-обмен сообщениями реализован через Laravel Reverb.

## Возможности

### Пользователи

- регистрация и авторизация;
- подтверждение email;
- восстановление пароля;
- редактирование профиля;
- загрузка аватара;
- публичные профили пользователей;
- возраст, город, пол и информация о себе;
- блокировка и разблокировка других пользователей;
- ограничение взаимодействия между заблокированными пользователями;
- административная блокировка аккаунта.

### Мероприятия

Пользователь может:

- создать мероприятие;
- сохранить его как черновик;
- редактировать;
- опубликовать;
- отменить;
- завершить;
- загрузить несколько фотографий;
- просматривать фотографии в карусели;
- просматривать профиль организатора.

Поддерживаются статусы:

- `Draft` — черновик;
- `Published` — опубликовано;
- `Ongoing` — проходит сейчас;
- `Completed` — завершено;
- `Cancelled` — отменено.

Статусы мероприятий автоматически синхронизируются через Laravel Scheduler.

### Каталог мероприятий

Доступен каталог опубликованных мероприятий с фильтрацией.

Мероприятия пользователей, между которыми существует блокировка, скрываются в соответствии с правилами доступа.

### Заявки на участие

Пользователь может откликнуться на опубликованное мероприятие.

Организатор может:

- принять заявку;
- отклонить заявку;
- добавить пользователя в лист ожидания;
- изменить решение до завершения мероприятия.

Пользователь может отозвать свою заявку.

Поддерживаются статусы:

- `Pending`;
- `Accepted`;
- `Rejected`;
- `Waitlisted`;
- `Withdrawn`.

Количество занятых мест учитывается при принятии и отзыве заявок.

### Чат

Между пользователем и организатором мероприятия может быть создан диалог.

Поддерживаются:

- realtime-сообщения через Laravel Reverb;
- Laravel Echo;
- аватар и имя собеседника;
- переход в профиль собеседника;
- статус прочтения сообщений;
- счётчик непрочитанных сообщений;
- запрет общения между заблокированными пользователями;
- сохранение истории переписки после блокировки;
- скрытие формы отправки сообщений при блокировке;
- перевод чата в режим только для чтения после завершения или отмены мероприятия.

При блокировке одного из участников существующая история сообщений остаётся доступной для чтения, но отправка новых сообщений становится недоступна для обеих сторон.

### Уведомления

Используются Laravel Notifications.

Создаются уведомления о:

- новой заявке;
- принятии заявки;
- отклонении заявки;
- новом сообщении.

Уведомления выполняются через Redis Queue.

### Отзывы и рейтинг

После завершения мероприятия:

- принятый участник может оставить отзыв организатору;
- организатор может оставить отзыв принятому участнику;
- рейтинг задаётся от 1 до 5;
- можно добавить текстовый комментарий;
- повторный отзыв тому же пользователю в рамках одного мероприятия запрещён.

В публичном профиле отображаются:

- средний рейтинг;
- количество отзывов;
- список полученных отзывов;
- автор отзыва;
- мероприятие, к которому относится отзыв.

### Блокировки пользователей

Пользователь может заблокировать другого пользователя через его публичный профиль.

После блокировки:

- ограничивается взаимодействие между пользователями;
- мероприятия заблокированного пользователя скрываются;
- отправка сообщений становится недоступна;
- существующий чат остаётся доступным только для чтения.

Пользователь может снять созданную им блокировку.

Снять блокировку, созданную другим пользователем, нельзя.

Администратор также может заблокировать аккаунт пользователя.

При административной блокировке:

- пользователь теряет доступ к аккаунту;
- сохраняется причина блокировки;
- сохраняется дата блокировки;
- активные мероприятия пользователя автоматически отменяются.

После административной разблокировки отменённые мероприятия автоматически не восстанавливаются.

### Жалобы

Пользователь может пожаловаться на:

- другого пользователя;
- мероприятие;
- конкретное сообщение в чате.

Для жалобы можно указать причину и дополнительное описание.

При жалобе на сообщение администратор видит контекст переписки:

- до 10 сообщений перед сообщением;
- сообщение, на которое поступила жалоба;
- до 10 сообщений после него.

Интерфейс визуально различает автора жалобы и второго участника переписки.

### Административная панель

Административная панель построена на Filament.

Доступ:

```text
/admin
```

Администратор может управлять:

- категориями;
- пользователями;
- мероприятиями;
- жалобами.

Для пользователей доступны административная блокировка и разблокировка.

При рассмотрении жалобы администратор может:

- открыть профиль пользователя;
- заблокировать пользователя;
- открыть мероприятие;
- отменить мероприятие;
- просмотреть контекст сообщения;
- заблокировать автора сообщения;
- изменить статус жалобы.

### PostgreSQL

Используется как основная база данных приложения.

В PostgreSQL хранятся:

- пользователи;
- профили;
- мероприятия;
- заявки;
- чаты;
- сообщения;
- отзывы;
- жалобы;
- уведомления;
- сессии.

### Redis

Используется для:

- Laravel Queue;
- Laravel Cache.

### Queue Worker

Отдельный Docker-контейнер постоянно обрабатывает фоновые задания:

```bash
php artisan queue:work redis
```

### Scheduler

Отдельный контейнер запускает:

```bash
php artisan schedule:work
```

Scheduler используется в том числе для автоматической синхронизации статусов мероприятий.

### Reverb

Laravel Reverb обеспечивает WebSocket-соединение для realtime-чата.

Внутри Docker Laravel обращается к:

```text
reverb:8080
```

Браузер подключается через:

```text
localhost:8080
```

# Установка и запуск

Инструкция ниже проверена на чистом клоне репозитория.

## Требования

Для запуска проекта необходимы:

- Git;
- Docker;
- Docker Compose.

PHP, Composer, Node.js, PostgreSQL и Redis отдельно устанавливать не требуется.

---

## 1. Клонирование репозитория

```bash
git clone https://github.com/Arka999io/event-app.git
cd event-app
```

---

## 2. Создание `.env`

Создайте `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

`.env.example` уже содержит конфигурацию локального Docker-окружения для PostgreSQL, Redis и Laravel Reverb.

---

## 3. Сборка Docker-образа

```bash
docker compose build
```

Docker-образ содержит PHP, Composer, Node.js, npm и необходимые PHP-расширения.

---

## 4. Установка PHP-зависимостей

Основные контейнеры на этом этапе ещё не запущены, поэтому Composer выполняется через временный контейнер:

```bash
docker compose run --rm --no-deps laravel.test composer install
```

После выполнения зависимости будут сохранены в директории `vendor/` проекта.

---

## 5. Установка frontend-зависимостей

```bash
docker compose run --rm --no-deps laravel.test npm install
```

---

## 6. Сборка frontend

```bash
docker compose run --rm --no-deps laravel.test npm run build
```

Vite создаст production-сборку frontend в `public/build`.

---

## 7. Запуск Docker-сервисов

```bash
docker compose up -d
```

Будут запущены:

```text
laravel.test
pgsql
redis
queue
scheduler
reverb
```

---

## 8. Генерация ключа приложения

```bash
docker compose exec laravel.test php artisan key:generate
```

Команда создаст уникальный `APP_KEY` в локальном `.env`.

---

## 9. Миграции и демонстрационные данные

Для первоначальной установки:

```bash
docker compose exec laravel.test php artisan migrate --seed
```

Команда создаст структуру PostgreSQL и заполнит базу демонстрационными данными.

Для полного пересоздания базы в дальнейшем:

```bash
docker compose exec laravel.test php artisan migrate:fresh --seed
```

> `migrate:fresh` полностью удаляет существующие таблицы и данные перед повторным выполнением миграций.

---

## 10. Создание storage link

```bash
docker compose exec laravel.test php artisan storage:link
```

Команда создаёт ссылку:

```text

```

Если Laravel сообщает:

```text

```

повторно создавать ссылку не требуется.

# Reverb

Reverb запускается автоматически через Docker Compose.

Посмотреть логи:

```bash
docker compose logs --tail=100 reverb
```

Используемая схема подключения:

```text
Laravel → reverb:8080
Browser → localhost:8080
```

В `.env` серверная и клиентская конфигурации разделены:

```env
REVERB_HOST=reverb
REVERB_PORT=8080
REVERB_SCHEME=http

VITE_REVERB_HOST=localhost
VITE_REVERB_PORT=8080
VITE_REVERB_SCHEME=http
```

`REVERB_HOST=reverb` используется Laravel внутри Docker-сети.

`VITE_REVERB_HOST=localhost` используется браузером.

# Основные бизнес-правила

## Мероприятия

- создавать мероприятия могут авторизованные пользователи в соответствии с правилами доступа приложения;
- пользователь не может откликнуться на собственное мероприятие;
- мероприятие может находиться в состояниях `Draft`, `Published`, `Ongoing`, `Completed` и `Cancelled`;
- завершённое или отменённое мероприятие нельзя использовать как активное;
- количество принятых участников ограничено количеством доступных мест;
- статусы мероприятий синхронизируются через Scheduler;
- отменённое мероприятие остаётся доступным для просмотра по прямой ссылке, но отображается как отменённое;
- для закрытого мероприятия нельзя начинать новое общение.

## Заявки

- заявка относится к конкретному мероприятию и пользователю;
- один пользователь не может создавать несколько независимых заявок на одно мероприятие;
- организатор может принимать и отклонять заявки;
- пользователь может отозвать свою заявку;
- поддерживается лист ожидания;
- принятие заявки учитывает количество свободных мест;
- изменение статуса заявки выполняется через бизнес-логику приложения.

## Отзывы

- отзыв можно оставить только после завершения мероприятия;
- отзывы разрешены между организатором и принятым участником;
- участник может оценить организатора;
- организатор может оценить принятого участника;
- нельзя оставить отзыв самому себе;
- рейтинг находится в диапазоне от 1 до 5;
- повторный отзыв тому же пользователю в рамках одного мероприятия запрещён;
- отзывы участвуют в формировании рейтинга публичного профиля пользователя.

## Чаты

- диалог относится к конкретному мероприятию;
- пользователь общается с организатором мероприятия;
- посторонний пользователь не может отправлять сообщения в чужой диалог;
- сообщения доставляются в realtime через Laravel Reverb;
- после завершения или отмены мероприятия чат становится доступен только для чтения;
- при блокировке одного из пользователей чат также становится доступен только для чтения;
- история переписки после блокировки сохраняется;
- форма отправки сообщения при блокировке скрывается;
- backend дополнительно запрещает отправку сообщения в заблокированный диалог независимо от состояния интерфейса.

## Пользовательские блокировки

- пользователь не может заблокировать самого себя;
- пользователь может заблокировать другого пользователя;
- пользователь может снять только созданную им блокировку;
- пользователь не может снять блокировку, установленную другим пользователем;
- блокировка учитывается в обе стороны при проверке возможности взаимодействия;
- после блокировки дальнейшее общение между пользователями запрещается;
- мероприятия заблокированных пользователей скрываются в соответствии с правилами видимости.

## Жалобы

- пользователь не может пожаловаться сам на себя;
- жалобы поддерживаются для пользователей, мероприятий и сообщений;
- посторонний пользователь не может пожаловаться на сообщение из чужой переписки;
- повторная активная жалоба на один объект запрещена;
- жалоба содержит причину и может содержать дополнительное описание;
- жалобы обрабатываются через административную панель.

При жалобе на сообщение администратор получает контекст переписки:

```text
до 10 сообщений до
        ↓
сообщение, на которое пожаловались
        ↓
до 10 сообщений после
```

Если в диалоге меньше сообщений, отображается доступная часть переписки.

## Административная блокировка

- заблокированный администратором пользователь не может пользоваться аккаунтом;
- сохраняются дата и причина блокировки;
- при блокировке активные мероприятия пользователя отменяются;
- пользователь не может обойти блокировку повторной авторизацией;
- после административной разблокировки доступ к аккаунту восстанавливается;
- отменённые при блокировке мероприятия автоматически не восстанавливаются.

## Модерация мероприятий

При жалобе на мероприятие администратор может отменить его непосредственно из интерфейса жалобы.

После отмены:

- мероприятие получает соответствующий статус;
- новые отклики становятся недоступны;
- новые сообщения становятся недоступны;
- жалоба может быть отмечена как решённая.

## Модерация сообщений

При жалобе на сообщение администратор:

- видит автора сообщения;
- видит пользователя, подавшего жалобу;
- видит само сообщение;
- видит контекст переписки;
- может заблокировать автора сообщения;
- может изменить статус жалобы.


Таким образом:

```text
Laravel container
       │
       └────► reverb:8080

Browser
       │
       └────► localhost:8080
```

# Тестирование чистой установки

Порядок первоначальной установки проекта был проверен на чистом клоне репозитория.

Рабочая последовательность:

```text
git clone
    ↓
cp .env.example .env
    ↓
docker compose build
    ↓
composer install через временный Docker-контейнер
    ↓
npm install через временный Docker-контейнер
    ↓
npm run build через временный Docker-контейнер
    ↓
docker compose up -d
    ↓
php artisan key:generate
    ↓
php artisan migrate --seed
    ↓
php artisan storage:link
    ↓
php artisan optimize:clear
    ↓
готовое приложение
```

Установка PHP- и frontend-зависимостей выполняется **до** `docker compose up -d`.

Это необходимо потому, что основной Laravel-контейнер, Queue Worker, Scheduler и Reverb используют Artisan и требуют существующий:

```text
vendor/autoload.php
```

Поэтому на совершенно новом клоне сначала выполняется:

```bash
docker compose run --rm --no-deps laravel.test composer install
```

а уже после установки зависимостей запускается полный Docker-стек.

# Безопасность

Файл `.env` не должен попадать в Git.

В `.gitignore` исключены:

```text
.env
.env.production
/vendor
/node_modules
/public/build
/public/storage
```

Также из репозитория исключаются:

- пользовательские загрузки;
- Laravel logs;
- скомпилированные Blade views;
- локальные cache-файлы;
- зависимости Composer;
- зависимости npm;
- production-сборка Vite.

`.env.example` содержит только демонстрационную конфигурацию локального окружения.

## Перед production-развёртыванием

Необходимо:

- установить `APP_ENV=production`;
- установить `APP_DEBUG=false`;
- сгенерировать уникальный `APP_KEY`;
- заменить пароль PostgreSQL;
- заменить Reverb credentials;
- настроить HTTPS;
- использовать production web server;
- настроить резервное копирование PostgreSQL;
- настроить безопасное хранение секретов;
- не использовать демонстрационные аккаунты;
- при необходимости настроить внешний mail provider;
- настроить мониторинг Queue Worker и Scheduler.

Текущий Docker setup ориентирован прежде всего на локальную разработку, демонстрацию и запуск проекта из репозитория.

Для production рекомендуется использовать отдельную конфигурацию с PHP-FPM и reverse proxy, например Nginx или Caddy, вместо встроенного Laravel development server.
